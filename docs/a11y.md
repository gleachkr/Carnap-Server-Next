# Accessibility testing

The application targets WCAG 2.2 AA. Automated checks catch regressions but
cannot establish conformance. Use all three kinds of testing below:

1. **Structural tests** run axe-core over server-rendered HTML in jsdom as
   part of `bun test`.
2. **Browser audits** run axe-core in Chromium against a running server,
   including checks that depend on layout.
3. **Manual checks** cover keyboard use, screen readers, focus, zoom, and
   other behavior automation cannot reliably assess.

Palette-token and contrast calculations also run in `bun test`.

Enter the Nix development environment before running project commands:

```sh
nix develop
```

There is no CI or hook that runs these commands automatically. Structural and
palette tests are included when a developer runs `bun run validate`; browser
and manual audits are separate.

## Baselines

Structural and browser audits use committed baselines:

- `tests/a11y/baseline.json`
- `tests/a11y/baseline.browser.json`

**Gate mode** fails on findings absent from the baseline. **Report mode**
prints all current findings. An update command regenerates the baseline.

Review baseline changes before accepting them. Removing a resolved finding
makes a recurrence fail; adding a finding accepts it as known debt. Both
committed baselines are currently empty, which does not mean all pages or
manual criteria have been tested.

## Tier 1: structural tests

`tests/a11y/a11y.test.ts` audits the representative pages in
`tests/a11y/fixtures.ts`, including standalone exercise documents. The runner
in `tests/a11y/axe-runner.ts` disables layout-dependent rules such as
contrast,
target size, and visibility because jsdom has no layout engine.

The runner converts Declarative Shadow DOM templates to real shadow roots
before auditing. Otherwise axe would miss widget internals. A regression test
plants a fault inside a shadow root to verify that it is inspected.

```sh
bun test tests/a11y/a11y.test.ts
bun run a11y:report
bun run a11y:baseline
```

Add a fixture whenever you add a page template. The same fixture set supports
the internationalization checks; an omitted page is invisible to both suites.

## Palette tests

The palette tests are intended to check token definitions, fallback values,
and contrast ratios for known foreground/background pairs:

- `tests/a11y/tokens.test.ts` scans variable uses in TypeScript source.
- `tests/a11y/contrast.test.ts` extracts palettes from `CONTENT_STYLES` and
  calculates contrast without a browser.

**Current coverage gap:** these tests still assume the indentation used when
CSS was embedded in TypeScript. With the current `.css` files, the contrast
parser labels the dark `:root` block as “light” and finds no additional
palettes. The token parser can span both root blocks, and its source-file
scan excludes `.css` files. A passing run therefore does not establish the
claimed light/dark contrast or CSS-fallback coverage.

These parsers need updating before the arithmetic tests can be relied on for
both palettes. Until then, use browser audits and inspect token changes
manually. Even corrected arithmetic tests would cover only declared pairs,
not every rendered combination.

## Tier 2: browser audit

The browser audit requires a running development server and Chromium. It
checks rendered contrast, target size, content iframes, open shadow roots,
and enhanced widgets.

```sh
# Terminal 1
bun run dev

# Terminal 2
bun run a11y:audit
bun run a11y:audit:dark
bun run a11y:audit:report
node scripts/a11y-audit.mjs --update
```

The default server is on port 8787. Override the server or login account, or
supply extra routes, when needed:

```sh
node scripts/a11y-audit.mjs \
  --base=http://localhost:8787 --email=staff@example.edu
node scripts/a11y-audit.mjs /courses/COURSE/assignments/ASSIGNMENT
```

The script uses Node builtins and the installed `axe.min.js`, injecting axe
into each frame. It normalizes record IDs and positional selectors so the
baseline identifies component problems rather than particular database rows.

### Dark mode

Run both light and dark audits before a release. `--dark` emulates
`prefers-color-scheme: dark` in every frame. The application follows that
media query; it has no separate theme toggle or cookie.

Dark findings have a `dark ::` prefix. Updating one palette merges its
findings into the shared browser baseline without deleting the other
palette's entries.

### Language and overflow checks

The same browser harness can look for translation-related layout problems:

```sh
bun run i18n:overflow
```

This runs report mode with `--overflow --lang=en-XA`. `--lang` sends an
`Accept-Language` header; a `?lang=` query parameter does not select a locale.

Overflow checks report text clipped by its container or extending beyond the
viewport, including inside the content iframe. They exclude deliberate
scrolling areas such as wide tables and code blocks, and their descendants.
The findings are advisory and do not themselves change the exit status.

The script checks the resulting `<html lang>`. A mismatch for `en-XA` fails
even in report mode, since the test would otherwise measure the wrong
language. A mismatch for a real language warns; clear the audit account's
stored preference or use another account. See [i18n](./i18n.md).

## Tier 3: manual checks

Use [the manual checklist](./a11y-manual.md) before each release and after
substantial page or widget changes. Record the browser, screen reader,
release or change, and results.

## Color-token guidance

Use `--ink-muted` for secondary text on surfaces where it meets contrast
requirements. Use `--ink-muted-strong` on the light palette's warmer fills,
such as `--surface-soft`, `--paper`, and `--rule-soft`.

The strong token means **more contrast**, not **darker**. It is darker in the
light palette and lighter in the dark palette. Prefer the existing strong
token over changing ordinary muted text throughout the application.

`--ink-faint` is for decoration only. Do not use it for essential text,
glyph-only controls, or state indicators without checking their contrast.

Axe may report symbol-only content as `incomplete` rather than a violation
because it cannot decide whether the glyph is text or an icon. The gates
report violations, so manually check these controls. Text generally needs
4.5:1 contrast; essential non-text controls and indicators need 3:1.

### Known manual follow-up

The theory panel's disclosure triangle uses `--ink-faint` on
`--surface-soft`. Its light-palette contrast is below 3:1. Review whether it
is needed to identify the open/closed state or is redundant with another
visible indicator. Automated contrast checks do not settle that question.
